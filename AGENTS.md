# AGENTS.md

## Cursor Cloud specific instructions

This repository is a single native **Android** app (Kotlin + Gradle), package
`com.mikelcalvo.batteryalarm` ("Battery Alarm"). There is no backend, database,
or web service — it builds an APK that runs on an Android device/emulator.

### Toolchain (already installed in the VM snapshot)
- **JDK 17** at `/usr/lib/jvm/java-17-openjdk-amd64`. This is required: Gradle 7.5
  / AGP 7.4 do **not** work with the system default JDK 21. `JAVA_HOME` is set to
  JDK 17 in `~/.bashrc`, so interactive/login shells use the right Java
  automatically. Non-login shells must export `JAVA_HOME` themselves.
- **Android SDK** at `~/android-sdk` (`ANDROID_HOME`/`ANDROID_SDK_ROOT`), with
  `platform-tools`, `platforms;android-33`, `build-tools;33.0.2`, `emulator`, and
  `system-images;android-33;google_apis;x86_64`. `adb`, `sdkmanager`, and
  `emulator` are on the PATH via `~/.bashrc`.
- `local.properties` (gitignored) is regenerated by the startup update script to
  point Gradle at the SDK.

### Build / lint / test (run from repo root; standard Gradle tasks)
- Build debug APK: `./gradlew assembleDebug` (output: `app/build/outputs/apk/debug/app-debug.apk`)
- Unit tests: `./gradlew test`
- Lint: `./gradlew lint` (report: `app/build/reports/lint-results-debug.html`)
- Instrumented tests (`./gradlew connectedAndroidTest`) require a running emulator/device.
- If `./gradlew` reports "Permission denied", run `chmod +x gradlew` (or `sh ./gradlew ...`).

### Running the app on the emulator (IMPORTANT caveats)
The VM has **no KVM / hardware virtualization** (`/dev/kvm` is absent), so the
emulator only runs in slow software mode. It works but with gotchas:
- Start headless with software GPU, e.g.:
  `emulator -avd batt -no-accel -gpu swiftshader_indirect -no-snapshot -no-boot-anim -no-window -cores 4 -memory 4096`
  (an AVD named `batt` already exists). Cold boot takes several minutes; poll
  `adb shell getprop sys.boot_completed` until it returns `1`.
- Under software rendering, `com.android.systemui` repeatedly throws
  "isn't responding" (ANR) dialogs that steal focus. Immediately after boot run:
  `adb shell settings put global hide_error_dialogs 1` and set the three
  animation scales (`window_animation_scale`, `transition_animation_scale`,
  `animator_duration_scale`) to `0` to keep the UI usable.
- Drive the UI with `adb shell input tap/keyevent` and capture state with
  `adb exec-out screencap -p > out.png`; record demos with `adb shell screenrecord`.
  The framebuffer reads black when the display sleeps — send `KEYCODE_WAKEUP`
  (and `adb shell svc power stayon true`) first.
- Install/launch: `adb install -r app/build/outputs/apk/debug/app-debug.apk` then
  `adb shell am start -n com.mikelcalvo.batteryalarm/.view.MainActivity`.
